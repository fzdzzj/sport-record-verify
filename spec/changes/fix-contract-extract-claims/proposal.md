# 提案：fix-contract-extract-claims（契约门提取与在途判定盲区修缮）

提案人：指导 Agent（2026-10-08）。状态：待派发。

## Why（为什么做）

契约门 `mailbox-contract.sh` 的判据 B 存在两层结构性盲区，已造成**四次同型过冲**（均登记在册）：TASK-160 G8、TASK-174 §1.2.1、TASK-181 §1.2.4（根因定位最完整）、TASK-182 C-02。每次过冲都迫使执行侧手工逐条核对自证清白（TASK-181 为此写了逐行核对的 `.trae/tmp` 日志 1206 行），本笔门槛读数长期带「rc=1 预期」脚注，侵蚀门的权威性。

**根因一（提取层「正文即声明」）**：`extract_claims`（L114-129）把「只改/改动/文件清单」小节正文里**所有**文件名样 token 一律提取为声明，包括「显式零触碰：… `pom.xml`」「未碰 … `pom.xml`」这类**否定句式**里的公共文件名（TASK-174 L43、TASK-005 L18-19 实例在册）；且小节缺失时**回退整档扫描**（L124 `cat` 全文），正文提及≠声明却全被当声明。

**根因二（在途判定层「文件名共占」）**：判据 B 仅以「清单与改动集文件名有交叠」判定在途回传（L182 `both>0`）。任何后续任务真实改动公共文件（`pom.xml` / `application.yml`）时，几十个**已收口**历史任务的"声明"（经根因一被污染，或真实声明过该文件）与当前改动集共占，被逐个拉进比对判「清单多报」→ 假阳性 rc=1。TASK-182 C-02 的 `--open` 在途门即为此红（历史 TASK-008/125 多报＋本笔新文件未声明两个方向同时触发）。

## What（做什么）

对 `scripts/verify/mvn-verify.sh` 旁路的 `scripts/verify/mailbox-contract.sh` 做三层修缮（判据 A 语义、退出码语义 0/1/2/3、`mvn-verify.sh` 零触碰）：

1. **提取层收紧**：清单小节内只认**列表行**（`^\s*(-|\d+\.)\s` 开头）中的文件名 token；行内含否定句式（零触碰 / 未碰 / 未触碰 / 不改 / 禁触）→ 该行不产任何 token；**删除全文回退**——小节缺失时 claims 为空，走既有「未解析到改动清单，跳过判据 B」分支并输出警示行；
2. **在途判定层重构**：判据 B 前置「回传文件基线变动」检查——`handoff.md` 相对基线既无 diff 也非 untracked ⇒ **已收口，直接不重审**（连共占计算都不做）；有变动才进入清单比对。「在途」定义由「文件名共占」改为「回传文件在本次作业窗内变动」，已收口历史任务不再可能被公共文件名拉进比对；
3. **兼容层**：`--diff-file` 模式下在途判定仍用 git（改动集来源与判定来源解耦）；非 git 上下文 + `--diff-file` 的组合降级为旧共占在途判定并输出注明行（该组合在仓内工作流不发生，登记为边界不拒跑）。

同步更新脚本头部用法注释与 `scripts/verify/README.md` 契约门专节的行为描述（仅该节）。

- **退出码语义零改动**：0 通过 / 1 契约红 / 2 参数错 / 3 来源不可判定，逐一保持；
- **不引入脚本测试框架**：验证用合成 fixture（临时台账目录＋假 handoff＋`--diff-file` 假改动集，全部落 gitignored 临时区）手工跑 rc 断言留证，不新建测试目录或 CI 步骤；
- **`mvn-verify.sh`、`ci.yml` 零触碰**；Java 侧六服务、api 模块、web、sql、pom 全部零触碰；
- **不追溯改写历史 handoff**：四次过冲的历史登记原文保留（先例纪律）。
