# 提案：提交路径默认走已验证的优化（可回退）

## Why

ADR-0002 已经用实测证明：轨迹逐条 INSERT 把提交接口钉死在 ~36 QPS（Hikari 10 连接 × 每请求约 300 次 INSERT）。改成单分片批量 INSERT 后，100 并发 **35.5 → 136.8 QPS（3.9×）**，P95 **3.76s → 1.60s**。

但优化开关现在是关的：

- `record.track.batch-insert-enabled=false`（`application.properties` 与 `@Value` 默认都是 false）
- 连接池 `maximumPoolSize: ${MYSQL_POOL_SIZE:10}` 仍是压测基线值

也就是说：**仓库里「已优化」只存在于压测报告和一次手动开开关的跑法，日常启动仍走被证伪的慢路径。** 这不是新瓶颈，是已验证优化没有成为默认。

再去调 `innodb_flush_log_at_trx_commit`、盲目加大堆、再拆服务，都没有把默认路径切到已有 3.9× 来得有证据。

**背景**：
- 压测优化案例已归档（ADR-0002 / `docs/perf/压测报告.md`），开关保留是为了「可回退、可复现基线」。
- 「默认可回退」被实现成了「默认关闭优化」。
- ADR-0002 后续项里的库刷盘参数、MQ 异步化、突发 P95 调消费线程，本变更不做。

**当前状态**：演示 / README 快速开始 / 不带环境变量启动 = 逐条 INSERT + 10 连接。

**期望状态**：默认走批量 INSERT（已验证路径）；基线复现改为显式关闭开关。连接池默认仍 10，避免把「开批量」和「改池大小」两件因果缠在一起。池大小继续用 `MYSQL_POOL_SIZE` 注入，与 ADR-0002 一致。

## What Changes

- `record.track.batch-insert-enabled` 默认改为 `true`（properties 与 `@Value` 缺省一致）。
- README / 压测报告 / ADR-0002 写清：日常默认优化路径；复现无批量基线须显式 `record.track.batch-insert-enabled=false`。
- 保留开关与逐条代码路径，禁止删掉基线实现。
- 不改 `MYSQL_POOL_SIZE` 默认 10；不改 InnoDB 刷盘；不改 GC 堆；不改 MQ 消费参数。
- 单测锁定：开关 true 走 `insertBatch`，false 走逐条 `insert`（已有测试则只改默认相关断言）。

**明确不做**：

- 不上新压测平台、不上 JMeter。
- 不把 `innodb_flush_log_at_trx_commit` 改成 2 来刷吞吐（耐久性换数字，不诚实）。
- 不固定大堆（ADR-0002 已否决）。
- 不在本变更重跑 100/500/1000 全量压测（需要六服务+中间件长时间占用；数字仍以 ADR-0002 CSV 为准）。若用户要复测，另开变更。
- 不改点赞/榜单/校验引擎算法，不开新业务模块。
- 不动 S1/S2 未归档目录的正文。

## Impact

### 受影响的规范
- `spec/specs/sport-record-verify/spec.md` — ADDED「提交路径默认批量插入」；必要时 MODIFIED「瓶颈优化实录」说明默认走优化路径、基线可回退。

### 受影响的代码
- `record-service`：`application.properties`、`SportRecordService` 缺省值
- 文档：README、ADR-0002、压测报告相关段落
- 测试：批量/逐条开关断言

### 用户影响
- 不改 API。新启动的 record-service 提交轨迹默认更快；要复现 36 QPS 基线必须关开关。

## 时间线评估

小：约 0.5 天（改默认 + 文档 + 测试对齐）。

## 风险

- **压测「无批量基线」被默认值破坏** → 缓解：开关保留，文档写明复现步骤必须显式 false。
- **有人把默认 true 理解成「还要默认池 30」** → 缓解：本变更明确不改池默认，避免两因一果。
- **超长轨迹单语句过大** → 缓解：已有单批上限 500，不改。
- **不重跑压测被质疑「没有新数字」** → 缓解：本变更不声称新 QPS；只把 ADR-0002 已验证路径设为默认。新数字另开复测变更。

## 备注

ADR-0002 仍开放的性能后续（本变更不纳入）：突发端到端 P95（消费线程/拉取批次）、提交侧跨请求聚合、MQ 异步化。那些没有新测量就动，会把已达标口径搅浑。
