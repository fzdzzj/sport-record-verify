# 交付说明：规则灰度发布（rule_version 快照 + userId%100 采样 + 秒级回滚）

> 变更提案：[proposal.md](proposal.md) ｜ 规范差异：[spec-delta.md](specs/sport-record-verify/spec-delta.md) ｜ 选型决策：[ADR-0004](../../../docs/adr/0004-规则灰度发布.md)

## 0. 一句话总结

规则阈值从「Nacos 一刀切、一改全体生效」升级为「版本化快照 + 按用户采样灰度 + 异常秒级回滚 + 稳定一键全量」，`rule_version` 表从摆设变成判定关键路径。

## 1. 为什么做（变更动机）

- 此前阈值只能改 Nacos 全局生效：新规则有 bug 全体用户直接承担误判；没有「先小流量验证」的缓冲。
- 审批版 §7.4 已设计完整灰度流程，`rule_version` 表已建但无任何代码使用——本变更把设计变成实锤（面试弹药 J：Nacos 灰度发布 + 秒级回滚）。

## 2. 最终效果（你能看到什么）

管理端三接口（经网关，StripPrefix=1）：

| 操作 | 接口 | 效果 |
| --- | --- | --- |
| 创建版本 | `POST /verify/rules/versions` | 快照 rules_json 落库，状态 GRAY（body 可带新阈值 `rules` 与初始 `grayRatio`，缺省快照当前基线） |
| 调灰度 | `PATCH /verify/rules/versions/{id}/gray` | 0-100；`userId%100 < gray_ratio` 的用户走快照；**置 0 = 秒级回滚** |
| 全量发布 | `POST /verify/rules/versions/{id}/activate` | gray=100 + ACTIVE，旧版本（ACTIVE/遗留 GRAY）全部 RETIRED |

运行时路由（校验入口每次判定）：命中采样 → 库内灰度快照；未命中 → 基线（ACTIVE 快照，无版本时 Nacos 实时配置）。同一用户恒定同分支。

## 5. 验证实录（本会话真实跑过，非「应该能行」）

环境：compose 中间件（MySQL:3307 / Nacos / Redis / RocketMQ 全 healthy）+ 宿主机 jar 启动 gateway/record/verify；判定走真实链路 提交 → RocketMQ SUBMITTED → verify 消费 → 灰度路由判定 → Feign 回调 record 迁移状态。

测试载体：版本 v-smoke-1（快照 r1.speed=6.6，基线 5.5），同一 **5.8 m/s** 匀速轨迹（基线应拒、快照应过）：

| 场景 | 用户 | 结果 | 结论 |
| --- | --- | --- | --- |
| 灰度 10%（gray_ratio=10） | 105（%100=5<10 命中） | verdict=PASSED，score=50，无规则命中 | 灰度分支用快照 6.6 放行 ✅ |
| 灰度 10% | 150（%100=50 未命中） | verdict=REJECTED，R1_SPEED HARD（5.8>5.5） | 基线分支拦截 ✅ |
| 回滚（PATCH gray=0） | 105 再提交 | verdict=REJECTED（R1 拦截） | **立即**回归基线，本实例秒级生效 ✅ |
| 全量（activate） | 150 再提交 | verdict=PASSED | 新基线 6.6 对全员生效，旧版本无歧义退役 ✅ |

- Redis 广播：容器内 `redis-cli subscribe verify:rules:invalidate` 两次捕获负载 `"1"`（调灰度与回滚各一次）；verify 日志同秒出现「广播已发送」+「收到广播，本地路由缓存已清」。
- DB 终态：`rule_version` id=1 status=1(ACTIVE) gray_ratio=100；四条 `verification_result` 与上表一致；`sport_record` 状态回调闭环（2=PASSED / 3=REJECTED）。
- 负例：对 ACTIVE 调灰度 4003「仅 GRAY 版本可调灰度比例」；重复版本号 4004；比例越界 4004；不存在版本 4002——四个错误码全部按设计返回。
- `mvn clean install` 全仓 BUILD SUCCESS（verify-service 33 测试 0 失败）。

## 6. 边界与遗留（诚实口径）

- 管理接口 Swagger 级无鉴权（项目骨架无 JWT），生产须加管理员鉴权与审计。
- 分版本误判率对比监控（gray/active 打点）未做，属后续可观测项；当前靠 rule_hits 证据 JSON 离线对比。
- 灰度比例调整/回滚已秒级（本实例即时 + Redis 广播扇出）；Redis 整体不可用时全网退化 ≤60s TTL 收敛（规范允许上界）。
- spec-delta 待 openspec archive 合入 `spec/specs/sport-record-verify/spec.md` 基线（与既有变更口径一致）。
