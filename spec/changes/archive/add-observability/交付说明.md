# 交付说明：可观测性与监控告警（Prometheus + Grafana）

> 本文目标：**不用看源码**，读完即掌握 add-observability 变更做了什么、为什么这么做、怎么用、怎么验证。
> 关联：proposal.md（目标与理由）、specs/sport-record-verify/spec-delta.md（验收 Scenario）、docs/adr/0003-监控选型.md（选型理由）。

## 0. 一句话总结

给整个系统装上"仪表盘 + 自动报警"：四个服务的运行状况（内存、请求量、耗时、错误率、数据库连接池、GC）
由 Prometheus 自动定时采集，在 Grafana 预置面板上实时展示，越过阈值自动触发告警。
共 6 个 commit，全部实测验证通过（编译、端点、抓取、面板、告警评估）。

## 1. 为什么做（变更动机）

| 现状痛点 | 本变更带来的改变 |
| --- | --- |
| 服务只有 health（活着没）和 info（版本信息）两个检查端点，出问题只能翻日志 | 运行指标持续采集，趋势可视化，问题在变坏前就能看到 |
| "监控告警"只能讲设计，没有可演示的东西 | 现场可演示：停掉任一服务，1 分钟后告警变红 |
| 压测报告（add-load-test-report）的 P95/吞吐数据是一次性快照 | 同口径指标有了持续观测载体，优化效果可长期验证 |
| 需求书（审批版 §8.2）要求 P95 < 200ms，但没有手段持续盯 | P95 面板 200ms 红线 + 超线 2 分钟自动告警 |

## 2. 最终效果（你能看到什么）

`docker compose up -d` 一次性拉起中间件 + 监控栈（监控是其中两个容器），然后：

| 入口 | 地址 | 能看到什么 |
| --- | --- | --- |
| Prometheus 控制台 | http://127.0.0.1:9090 | Status→Targets：每个服务"采没采到数据"；Alerts：告警亮灯状态 |
| Grafana 面板 | http://127.0.0.1:3000 | 账号 admin/admin，打开预置面板「运动记录校验系统 · 全局监控总览」（8 块图） |
| 指标端点 | `curl http://127.0.0.1:8081/actuator/prometheus` | 任意服务的原始指标文本（jvm_ / http_server_requests_ / hikaricp_ 前缀） |

### 2.1 预置面板的 8 块图

1. **服务可用性**：每个服务绿（UP）红（DOWN）。
2. **HTTP QPS**：每秒处理多少请求，按服务分线。
3. **P95 延迟**：95% 的请求快于多少秒；200ms 处画红线（需求书 §8.2 的验收线），越线即变红。
4. **5xx 错误率**：服务端出错请求占比，5% 红线。
5. **JVM 堆内存**：已用与上限两条线（上限线取有固定上限的分代）。
6. **GC 暂停耗时**：每秒花在垃圾回收上的秒数，持续偏高说明内存压力大。
7. **数据库连接池**（HikariCP）：活跃/空闲/等待三线；"等待"持续大于 0 = 连接不够用
   （压测报告里"连接池 10→30 调优"的场景以后可直接在此观察）。
8. **JVM 线程数**：随并发增长的趋势，配合压测定位线程池容量。

### 2.2 四条自动告警（prometheus/alert-rules.yml）

| 告警名 | 触发条件 | 级别 | 阈值依据 |
| --- | --- | --- | --- |
| ServiceInstanceDown | 连续 1 分钟采不到数据 | critical | 15s 抓取周期 × 4 次，容忍单次网络抖动 |
| HttpErrorRateHigh | 5xx 占比连续 2 分钟 > 5% | warning | 95% 可用性对应 5% 错误预算（通用 SLO 惯例） |
| HttpP95LatencyHigh | P95 连续 2 分钟 > 200ms | warning | **审批版 §8.2 延迟预算**（网关 10ms + 落库 50ms + 校验 100ms ≈ 160ms） |
| JvmHeapUsageHigh | 堆使用率连续 5 分钟 > 80% | warning | 提案/spec-delta 明确口径，留 20% 余量防 GC 抖动误报 |

说明："连续 N 分钟"（for 参数）是为了防抖——瞬时毛刺不报警，持续异常才报。
告警目前只在 Prometheus 控制台亮灯；接邮件/钉钉需要 Alertmanager，属后续项。

## 6. 边界与遗留（诚实口径）

- 告警只"亮灯"不"通知"：邮件/钉钉/电话需对接 Alertmanager，后续项。
- RocketMQ 消息积压等中间件内部指标未采集（需 broker 暴露或 exporter），本变更聚焦 JVM/HTTP/DB 指标。
- `/actuator/prometheus` 目前在服务主端口直接暴露，**仅限本地演示**；生产要内网抓取 + 网关不转发 actuator。
- leaderboard-service（另一提案）上线后：取消 prometheus.yml 里的注释空位 + 在告警规则的 job 正则里加一个名字。
- gateway/record/verify 未启动时 Targets 页显示 DOWN，不是故障。
- spec/specs 基线（spec.md）未同步本能力域，待 openspec archive 步骤统一归档。
