# 提案：证明 outbox 批量标记 SENT 的语义边界（TASK-153）

## Why

TASK-152 在本机四服务单轮 c100×2000 中，`markSent` 的 MySQL 服务端语句事件总墙钟为 26,750.519526 ms，relay 22 批外层日志 `markMs` 合计 36,183 ms；计数 2010=2010=2010 配平。TASK-152 收口后已订正每批毫秒截断边界（提交 `abfc477`）：73.93% 是日志整数值的商，不是生产通用占比或优化收益。一次请求一个 `UPDATE` 是值得验证的成本假设，但**减少 SQL 次数是否安全、是否提速均未证明**。

现有 relay 按 ID 顺序逐行 `syncSend`，成功后立即条件 `markSent(id)`（自动提交）；失败则逐行 `incrRetry`。把成功行留到批末再更新，可能扩大崩溃后重复投递范围、延迟 `SENT` 的独立连接可见性、压平 `sent_at`，并改变部分标记失败或锁过期时的结果。消费端 eventId/业务锚点去重只能缓解重复造成的业务效果，不能自动证明这些差异可接受。因此先做 **GO/NO-GO 语义证明**，不直接把候选改进生产路径。

## What Changes

1. 冻结 HEAD `abfc477c1cad64c4885125e7cf10830fdc94e540`、既有脏项与 TASK-152 证据；逐条阅读 relay、Mapper、outbox DDL、消费者幂等/锁与现有规范。建立现状事实表：每次发送成功后的标记/可见性、失败后的重试、原 eventId、条件更新、`sent_at`、单轮锁、下轮重扫。区分规范硬约束、测试观察和待决策的行为变化。
2. 在**独立 scratch MySQL** 使用仓库真实 DDL 和真实 SQL/Mapper 构造至少两条事件，对照逐行基线与**仅测试中模拟的**批末更新候选。真实数据库验证：发送第 1 行成功后、第 2 行发送或标记失败前的独立连接状态；第 k 条发送后批末标记前模拟进程退出/重扫，计算会额外重复投递的行及 eventId；部分 SQL 更新异常/条件命中 0、混合成功与发送失败、重试耗尽、`sent_at` 时序；必要时用并发连接验证锁过期反例。模拟发送可控，但不能以 Mockito 预置数据库结果冒充真实 SQL。绝不把 scratch 结果称为完整 RocketMQ/Redis 端到端通过。
3. **默认 NO-GO**：若候选使任何既有可靠投递/可见性/状态/重试约束产生未经授权的变化，或仅能靠消费端去重掩盖扩大后的重复窗口，记录最小反例并停止，不写生产批量 Mapper/relay，不跑大负载。只有从规范与真库证据能证明语义不变，才可写后续*另立*的性能实施提案；本任务仍不实现生产优化。即使 GO 也只表示可进入同负载试验，不表示已提速。
4. 交付 test-only 判别 IT、报告与低基数机器摘要、三件套据实勾选、TASK-153 spec/handoff 与 PLAN/机会总览；离线 verify-service 常规测试与条件真库 IT（跳过不算通过）、JSON、`git diff --check`、无参数 mailbox 契约。只提交本任务文件，本地必要业务/台账两笔提交，不 push/PR。不运行 `c100×2000`，不修改生产 Java/SQL/YAML/默认参数、演示库、数据卷、宿主 Redis 服务。

## Impact

- 规范：仅为 `sport-record-verify` 增加候选批量标记的证据与停止门槛；不把现有「按行投递并标 SENT」规范改为批量语义。
- 文件：隔离 IT（test-only）、`docs/perf/` 报告及 JSON、三件套、TASK-153 两件套、PLAN/机会总览；原始 SQL/测试日志留 ignored `docs/perf/data/raw/task153-*`。不得新增生产特性开关或依赖。
- 数据：只创建专用 scratch schema（例如 `task153_batch_scratch`），不得改动演示 `verify_db`、已有 scratch schema 或任何数据卷；不可用即未覆盖而非假绿。
- 保留既有 archive 移名、`.codex/`、`.trae/`、`add-verify-degrade-status-index/`；不 stash、不 `git add -A`。

## 判定与停止条件

最强反例是「首条已同步发送、尚未批末标记时进程退出」：现行逐行路径会已提交 `SENT`，批末方案会留下更多 `PENDING` 待重发。消费者去重有 TTL 和业务锚点，不能推导发送次数、数据库可见性、操作告警均相同。若未能在真实 SQL 与代码路径上排除或明确获得规格授权，即裁决 NO-GO；不得以单轮 73.93% 份额直接实施批量化。测试仅回答语义可行性，不是吞吐对照或服务器成本拆项。
