# sports 项目 24 方向优化提案

## 目标
基于 Better Harness 评审发现的 9 条发现，分批优化 24 个方向，提升系统质量、性能和可维护性。

## 范围外
- 不改动业务逻辑核心流程
- 不引入破坏性变更
- 不修改已验收的测试用例断言

## 步骤
**第一批（高优先级，本周）**：
1. 测试质量（补单元测试覆盖边界场景）
2. 缓存体系（Redis+ 本地二级缓存，解决 F13 多实例不一致问题）
3. 异步消息 & 事件驱动（文档摄取流程异步化）
4. 任务调度系统（每日质量报告生成）
5. 数据一致性与事务（统一事务切面）

**第二批（中优先级，下周）**：
6. 数据库与 SQL（慢查询分析与索引优化）
7. API 契约设计（版本管理与兼容性）
8. 容错降级（熔断器与重试策略）
9. 安全加固（SQL 注入防护与权限审计）
10. 可观测性（日志结构化与链路追踪）

**第三批（低优先级，后续）**：
11-24. 分布式基础能力、配置管理、序列化、DDD 重构、资源管控、第三方 SDK 治理、版本兼容、研发工程、流量治理、数据治理、缓存增强、权限模型、部署运维、依赖治理

## 关键决策
- 所有优化采用 TDD 驱动（先写测试再实现）
- 每批次完成后需通过 CI 门禁（mvn verify + 覆盖率≥60%）
- 优先解决 F13 提到的"判定结果缓存多实例不一致窗口"问题
- 子 agent 只读自己的 spec.md，不跨文件猜测

## 验收标准
- 每个 TASK 有独立的 spec.md 和 handoff.md
- 代码提交前验证 status 干净
- commit message 格式："feat(TASK-XXX): 简短描述"
