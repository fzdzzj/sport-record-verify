# ADR-0006：空间匹配——道路拓扑匹配独立服务与 R5 离路规则

日期：2026-09-12
状态：已采纳（add-mapmatch-service 变更交付）

## 背景

- 校验引擎 R1-R4 是「启发式规则链」（速度/加速度/停留/距离一致性），本质是**对轨迹自身反常的检测**——识别不了「轨迹不在任何真实道路上」。这是最隐蔽的一类伪造：速度、加速度、距离都「正常」，但整条轨迹悬浮在海面/楼顶/田野直线穿越。审批版 §2.1 的 OSM 拓扑匹配原为「讲设计」未落地；执行计划 P2 将其列为进度超前才做的技术天花板项。
- 引入空间真实性判定有三个前置决策：独立服务还是内嵌 verify？真实路网还是手工假数据？什么匹配算法？服务数 5→6。

## 决策

### 1. 独立 mapmatch-service（第 6 服务），空间职责不进 verify-service

- 空间数据（OSM 路网，切片后仍是万级边）与匹配算法有独立的资源画像（内存驻留路网、CPU 密集垂距计算），与校验引擎的事件驱动批处理互相挤占；独立成服务可独立扩缩容、独立演进（换 HMM 算法/扩全国路网不动校验引擎）。
- R5 是首个**依赖外部服务的规则**：verify 侧只留规则与阈值（`R5OffRoadRule` 实现 `Rule` 接口 + Feign 调用），空间计算全部在 mapmatch——Rule 接口「新规则零改动接入聚合框架」的可扩展性首次吃到远程规则红利，VerifyEngine 聚合逻辑零改动。
- 依赖边界与 ADR-0005 同哲学：mapmatch 不反查任何业务库（输入轨迹点、输出指标，纯无状态计算）；verify→mapmatch 单向依赖，熔断降级隔离故障面。

### 2. PostGIS 承载真实 OSM 路网，不用内存图/手工数据

- **为什么真实 OSM**：手工假路网只能演示「算法能跑」，讲不了「全国路网分片/瓦片/更新」的工程化；真实数据才暴露真实问题（路网密度差异、缺失路段、数据截断）。选单城市切片（Overpass 下载上海人民广场周边 bbox，与压测样本基准点 31.2304,121.4737 同区域），体积与导入成本可控。
- **为什么 PostGIS 而非 MySQL 空间扩展/内存图**：路网匹配的核心查询是「半径内候选边」（`ST_DWithin` + GIST R-Tree 索引），PostGIS 是空间计算事实标准；MySQL 空间函数与索引支持弱；内存图（如 GraphHopper）是 HMM 全局匹配的选择，对「最近边投影 + 偏离度」过度设计。docker-compose 独立 postgis 服务（postgis/postgis:16-3.4），road_db 独立于业务三库。
- **导入链路幂等**：Overpass 下载切片（数据文件不入库）→ 零依赖 JDK21 单文件 `OsmImporter.java`（StAX 解析，沿用 scripts/perf 套路，不引 osm2pgsql 镜像）→ `road_edge` 表（TRUNCATE 重灌 = 覆盖刷新）+ GIST 索引（IF NOT EXISTS）。脚本可反复执行。

### 3. 匹配算法：最近边投影先跑通，HMM 进阶

- **先落最近边投影**：逐点独立吸附——GIST 索引预筛候选边（`ST_DWithin` 半径按 85km/度保守过覆盖，宁多筛不漏筛），Java 局部等距圆柱投影逐线段算垂距（小范围平面数学误差厘米级、可单测）。对「离路比例」这一粗粒度判定指标足够，且每段几何可解释（detail 带 avg/max 垂距）。
- **HMM 留进阶的原因**：最近边投影逐点独立，在密集交叉口吸附归属可能抖动；HMM 用转移概率约束全局一致性，但需要路网拓扑连通图与转移矩阵，复杂度 O(N×候选边²)。当前判定目标是「离路比例是否超阈」而非「精确重建行驶路径」，先用最小可用版跑通闭环（提案既定决策：卡壳时降级为最近边投影交付，HMM 与全国路网讲设计）。
- **防超时**：采样上限 200 点均匀抽稀（首尾保留，占比指标无偏）+ 查询半径 300m 封顶（无候选边按半径计离路，指标有界）——R5 在校验链路内同步调用，参数共同收敛延迟上界。

### 4. R5 判定与降级：SOFT 默认、极端偏离升级 HARD、降级不命中

- 阈值：offRoadRatio >0.5 记 SOFT（真实沿路轨迹实测 ≈0，50% 给沿河绿道/公园弱路网场景留余量）、>0.8 升级 HARD（整段悬浮作弊特征明确，HARD-SOFT 之间为灰度观察带）。`verify.rules.r5.*` 与 R1-R4 同源可配，复用 rule_version 灰度机制可先灰度观察再全量。
- 降级口径（对照 T11 熔断降级）：Resilience4j 熔断（10 次窗口 50% 失败率 → OPEN 10s → 半开 3 次，与 record-service 同参数）+ FallbackFactory 抛 4005，R5 捕获后**降级为「不命中」返回 null** 记 warn——路网匹配是增强证据而非强依赖，宁可放过不可阻断校验主链路。

## 备选否决

- **匹配逻辑内嵌 verify-service**：空间数据/算法与校验引擎耦合，无法独立扩缩容与演进，「为什么 6 个服务」无实体载体；且 verify 无空间库运维面。
- **手工假路网**：能演示算法但无工程化叙事（数据获取/导入/分片/更新），与提案「真实 OSM 路网数据（非手工假数据）」决策相悖。
- **osm2pgsql 导入**：面向国家级全量数据，产出表结构冗余且需额外镜像；单城市切片 StAX 自写导入更轻（与仓库零依赖单文件工具传统一致）。
- **HMM 一步到位**：判定指标是粗粒度占比，最近边投影已足够；HMM 的拓扑图/转移矩阵成本前置无收益，留作算法升级路径。

## 后果

- 正面：校验能力从「规则链」升级为「规则链 + 空间真实性」双保险，悬浮类伪造（此前完全穿透）被 R5 识别；「为什么校验引擎不只有 if-else 还要空间计算」成为可讲的架构决策（真实 OSM 数据链路、空间索引原理、离路阈值工程化）。
- 代价：多一服务的部署/内存开销（演示机 6 JVM）+ postgis 容器；R5 为校验链路引入同步远程调用（Feign 3s 读超时 + 熔断快速失败收敛）；离路比例阈值在弱路网区域（河道/公园/跨海）有误判面——SOFT 默认 + 灰度可回滚 + per-road-type 差异阈值列为后续项。
- 验收实录：`mvn clean install` 8 模块通过；postgis 容器 healthy、路网 7780 条边可查、导入脚本幂等重跑通过；沿南北高架真实轨迹 PASSED（hits 空）；黄浦江江面悬浮轨迹 REJECTED（`R5_OFFROAD/HARD off-road ratio 1.00, avg 143m, max 161m`，score 70=50+20×HARD）；停 mapmatch 后提交 → 校验正常完成 PASSED + verify 日志「R5 降级不命中」warn；Nacos 6 服务可见。
- 已知边界：路网切片范围有限（bbox 内才有路网，跨区轨迹会整段离路——生产化需全国分片/多切片路由）；R5 尚未接入 rule_version 灰度采样 UI（阈值走 Nacos 可配，灰度机制天然兼容）。
