# ADR-0001：版本矩阵与技术选型记录

- 状态：**已接受**
- 日期：2026-04
- 关联变更：`spec/changes/add-microservice-skeleton/`

## 背景

仓库从「审批基线文档」首次落地为可编译工程。审批版 §3.3 已定稿版本矩阵，
本 ADR 记录骨架阶段的落地决策与理由，供后续变更引用，避免重复讨论。

## 决策

### 1. 版本矩阵锁定（勿单独升级）

| 组件 | 版本 | 理由 |
| --- | --- | --- |
| Java / Spring Boot | 21 / 3.2.4 | 官方矩阵中 Boot 3.2.x ↔ Cloud 2023.0.x 兼容 |
| Spring Cloud / SCA | 2023.0.1 / 2023.0.1.0 | SCA 2023 分支官方版本 |
| Nacos / Sentinel | 2.3.2 / 1.8.6 | 与 SCA 2023.0.1.0 集成 |
| MyBatis-Plus | 3.5.7（spring-boot3-starter） | 支持 Boot 3 / JDK 21 |
| ShardingSphere-JDBC | 5.4.1 | track_point 分片（user_id % 16）依赖 |
| Redisson | 3.27.2 | 分布式锁/幂等（账号锁定、榜单结算防重） |
| RocketMQ | 5.2.0 服务端 + starter 2.3.1 | 独立集成，见决策 4 |
| Caffeine / Lombok | 3.1.8 / 1.18.30 | 二级缓存读侧 / 样板代码 |

**为什么 Boot 3.2.4 不升 3.3**：Spring Cloud Alibaba 2023.0.1.0 官方兼容矩阵只覆盖
Boot 3.2.x；升 3.3 会引入 SCA 与 Cloud 组件的版本冲突，风险不可控。骨架阶段锁定，
后续若官方矩阵更新再单独开变更升级。

**JDK 版本强校验**：父工程 `maven-enforcer-plugin` 要求 JDK ≥ 21，低于 21 直接编译失败
并提示「本工程要求 JDK 21 及以上」。

### 2. 统一响应与异常

所有 JSON 接口返回 `Result<T>`（`{code, message, data}`），错误码按审批版 §4.8 分段。
`common` 模块提供 `GlobalExceptionHandler`（`@RestControllerAdvice`），业务异常返回对应
错误码，未预期异常记完整堆栈、对外只返回 9999，不泄漏内部细节。服务启动类
`scanBasePackages = "com.sportverify"` 以加载 common 中的处理器。

### 3. MySQL 单实例三库

docker-compose 用**一个 MySQL 8 容器承载三个逻辑独立库**（user_db / record_db / verify_db）。
理由：开发环境资源友好，三个库在连接层完全隔离（各服务只连自己的库），符合「独立库」语义；
如需物理隔离，把 compose 中 mysql 拆成三个 service 并各自挂载对应 sql 脚本即可。

### 4. RocketMQ 独立集成（不随 SCA 走）

SCA 不内置 RocketMQ，采用官方 `rocketmq-spring-boot-starter 2.3.1` 独立集成。
Broker 配置 `brokerIP1=127.0.0.1`：本机 Java 服务是**宿主进程**（非容器），直连
`127.0.0.1:9876/10911` 才能互通；若把服务也容器化，需改为容器网络可达地址。

### 5. ShardingSphere 仅接入、默认关闭

record-service 引入 `shardingsphere-jdbc-core` 依赖（5.4.0 起 spring-boot-starter 模块移除、
`shardingsphere-jdbc` 退化为 BOM），但 `spring.shardingsphere.enabled=false`。
理由：分片表 track_point 的物理分片（user_id % 16）与校验引擎变更强耦合，本提案
「一个变更一个关注点」，只铺依赖不实现，避免 ShardingSphere × MyBatis-Plus 分页冲突
提前踩坑（提案风险缓解项）。

### 6. 中间件依赖接入策略（本阶段全部「接入不实现」）

| 依赖 | 所在服务 | 接入方式 |
| --- | --- | --- |
| Redisson | user-service | starter + `spring.data.redis` 配置，`RedissonClient` 自动装配 |
| RocketMQ | record / verify | starter + `rocketmq.name-server` 配置，producer 自动装配 |
| Caffeine | record / verify | 注册 `Cache` Bean（带容量/过期/统计） |
| Sentinel | gateway | 仅引入依赖，`spring.cloud.sentinel.enabled=false` 预留 |

### 7. Nacos 配置中心采用 `optional:` 导入

服务用 `spring.config.import: optional:nacos:{app}.yml` 拉取配置：Nacos 不可用时
**启动不失败**（只持续重试注册与连接，日志明确指向 Nacos），符合规范场景
「注册中心不可用 → 启动失败或持续重试」。生产环境可去掉 `optional:` 强制依赖。

## 后果

- 正向：版本冲突面收敛；新增模块零版本声明；一键起 + 一键编译，交付标准可复验。
- 负向：Boot 3.2.4 属上一代 Boot（2024 年 5 月 EOL 前的维护线），需在官方矩阵更新后单独升级；
  Sentinel/ShardingSphere 处于「依赖在、配置关」状态，接入真正能力前需回归验证启动链路。
