# ADR-0009：写路径事务边界

日期：2026-09-16
状态：已采纳（add-transaction-boundary-audit 变更交付）

## 背景

- 全项目写路径此前只有 3 处 `@Transactional`（`SportRecordService.submit` / `FriendService.accept` / `RuleVersionService.activate`），但缺少一篇「哪些写必须本地原子、哪些必须保持最终一致」的书面边界。
- 没有这篇边界，后续优化容易走两极：要么给 Service 批量铺注解，要么该回滚的路径没有回滚向测试。
- 点赞与榜单是 **Redis + DB 最终一致** 设计，不是漏加事务；交接里「注册插入 + 角色初始化必须原子」与代码不符——`role` 在 `user` 同一行（实体默认 USER + 表 `DEFAULT 'USER'`），注册一次 `insert`。
- 真正的风险是两类相反的错：（1）该原子的没测到回滚（如提交轨迹失败是否留下孤儿主记录）；（2）不该进本地事务的被顺手包进（点赞 Redis+DB、榜单 ZSet+贡献表、校验 Feign/MQ）。Spring 本地事务管不了 Redis / Feign / MQ；更糟的是若把 Redis 队列裁剪与 DB 写放进同一带事务方法，裁剪发生在 commit 前、随后回滚，会丢掉 pending。

## 决策

### 1. 四类边界（按路径分类）

| 类别 | 含义 | 本仓库代表路径 |
| --- | --- | --- |
| 必须本地原子 | 多行/多表 DB 写，中间失败必须全部回滚 | `submit`、`accept`、`activate`；flush 的 INSERT+DELETE |
| 刻意最终一致 | DB 与 Redis（或对账任务）分工，幂等可重放 | `like`/`unlike`、榜单 `applyVerified`/`rollbackOnRejected`/`settleAndReconcile` |
| 单行不必事务 | 单行写 + 唯一键/乐观锁幂等，不为形式加事务 | `register`、`grantAdmin`、`statusCallback`、`createRequest`/`reject` |
| 跨服务禁止本地长事务 | 本地事务（若有）不得包裹 Feign / MQ / 远程回调；不上 Seata | `verify`、`reviewAppeal` |

### 2. 分类表（对照代码复核，2026-09-16）

| 路径 | 写 | 现状 | 结论 |
| --- | --- | --- | --- |
| AuthService.register | user 一行 insert（role 同表默认 USER） | 无事务 | 保持。单行 + 手机号唯一键 |
| AuthService.grantAdmin | 一行 update | 无事务 | 保持 |
| AuthService.login/refresh/锁定 | Redis | 无事务 | 保持。禁止为 Redis 套 Spring 事务 |
| FriendService.createRequest/reject | 单写 + Redisson 锁 | 无事务 | 保持 |
| FriendService.accept | 申请状态 + 好友行 | 已有事务 | 保持。补回滚向测试/注释 |
| SportRecordService.submit | 主记录 + 轨迹 + 状态；MQ afterCommit | 已有事务 | 保持。补点插入失败不发 MQ 测试 |
| SportRecordService.statusCallback | 一行乐观锁 | 无事务 | 保持 |
| RecordLikeService.like/unlike | Redis 集合/计数 + pending 队列 | 无事务 | 禁止加。刻意最终一致 |
| RecordLikeService.flushPendingLikes | 批量插入 + 批量删除，成功后裁剪队列 | 本变更补本地事务 | 唯一补点：两 DB 写同一本地事务；裁剪在事务成功之后 |
| LeaderboardService.applyVerified/rollbackOnRejected | 一行贡献表 + ZSet | 无事务 | 禁止把 Redis 纳入事务。结算任务自愈 |
| LeaderboardService.settleAndReconcile | ZSet 纠偏 + 标记结算 | 无事务 | 保持最终一致 |
| RuleVersionService.activate | 退役 + 晋升 + 行锁 | 已有事务 | 保持（`SELECT ... FOR UPDATE` 必须在事务内） |
| VerifyService.verify | 占位写入 + Feign + upsert + MQ + 回调 | 无事务 | 禁止把 Feign/MQ 包进本地事务 |
| VerifyService.reviewAppeal | 申诉行 + Feign + MQ | 无事务 | 跨服务。已知残余，本变更不修 |

复核说明：`@Transactional` 全仓库仅上述 3 处（另加本变更 flush 经 `TransactionTemplate` 包裹 DB 两写，不在含 trim 的方法上直接标注解）。分类与代码不符时改本表，不准为凑数加注解。

### 3. flush 的唯一代码补点

- 同一批 `batchInsertIgnore` + `batchDelete` 必须同进退：用 `TransactionTemplate`（或可被 Spring 代理的独立方法）只包裹这两次 DB 写。
- `trimConsumed`（Redis `LTRIM`）**必须在事务成功返回之后**；禁止把含队列裁剪的方法直接标 `@Transactional`——否则回滚会丢掉 pending。
- 热路径 `like`/`unlike` 仍只写 Redis，不开启本地事务。

### 4. 禁止事项

- 禁止批量给 Service 加 `@Transactional`。
- 禁止给 `AuthService.register` / `login` / `grantAdmin` 加事务。
- 禁止用本地事务包裹 Redis ZSet 加减分 / 点赞计数 / Feign / MQ。
- 不上 Seata / 不用本地事务假装跨服务原子。
- 不改 `FriendService` 锁与事务的嵌套顺序（已知权衡：`@Transactional` 在方法入口开启，锁在方法内获取；本变更不借机重构）。

## 备选否决

- **注解铺满所有写路径**：形式主义；单行幂等与 Redis 写无收益，且误导「本地事务能跨 Redis/Feign」。
- **为注册补事务「保证角色初始化」**：角色不在第二张表，同一次 insert；加事务是假需求。
- **flush 整方法 `@Transactional` 含 trim**：裁剪若在 commit 前执行，DB 回滚后 pending 已丢，比现状更差。
- **引入 Seata 修 reviewAppeal**：跨服务缺口属已知残余，成本与运维面远超本变更范围；应用最终一致与补偿，而非分布式事务框架。

## 后果

- 正面：边界可审计；flush 同一批 like/unlike 落库原子；回滚向单测锁住「轨迹失败不发 MQ」「delete 失败不裁剪」「accept 两写同方法事务」。
- 代价：`RecordLikeService` 依赖 `PlatformTransactionManager`；单测需 stub 事务管理器。
- 已知残余：`reviewAppeal` 申诉行已改 + Feign 回调失败时的跨服务窗口，本变更不修；榜单 DB 与 ZSet 短暂不一致由结算任务以贡献表为准纠偏。
