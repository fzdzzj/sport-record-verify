# ADR-0008：规则读取二级缓存（Caffeine → Redis → DB 回填两级 + 三防护）

日期：2026-09-13
状态：已采纳（add-two-level-cache 变更交付）

## 背景

- 审批版 §7.3（弹药 I）完整设计了「Caffeine 本地 + Redis 中间层 + Nacos 失效监听」的二级缓存读路径与「穿透/击穿/雪崩」三防护，但此前 verify-service 只有单层 Caffeine（`CacheConfig`，1min TTL），二级缓存一直是「讲设计」。
- 规则快照/灰度路由低频变更、读多写少（每个 userId%100 采样都要读一次路由行，热点版本每判定都触发），值得为它们搭 Redis 中间层（跨实例共享，不必每实例各自查库）；而 Redis 单点可用性不如本地，需「降级 + 互斥 + 错峰」把风险压到最低。
- Redisson（RLock）、StringRedisTemplate、Caffeine 实例均已接入，本变更复用，无新中间件。

## 决策

### 1. 二级缓存只覆盖「规则快照/灰度路由」，判定结果维持单层 Caffeine

- 明确边界：只把 `RuleVersionService` 读的灰度/基线路由行（`verify:rules:gray`/`active`）与版本快照（`verify:rules:v{version}`）升级为二级缓存；**判定结果缓存**（`verify:result:{recordId}`，VerifyService）仍走单层 Caffeine——它有状态机幂等兜底，二级放大只会带来一致性负担而无收益。
- 抽象：`RuleCacheService.get(key, type, dbLoader)` 统一读路径（Caffeine → Redis → DB → 回填两级），`RuleVersionService` 的 `cachedRoute`/`snapshotRules` 改为委托其读取。

### 2. 三防护都落在 Redis 层

- **穿透（空值缓存）**：DB 查不到（如灰度版本号不存在）缓填空值哨兵（短 TTL 5s），防恶意/异常重复打库。
- **击穿（互斥重建）**：缓存失效并发重建同 key 时，用 Redisson 锁 `lock:rule-rebuild:{key}` 保证仅持锁实例查库；其余等待后 Double-check Redis 复用，拿不到锁降级无锁读一次（短超时 3s，不阻塞校验主链路）。
- **雪崩（随机 TTL）**：Redis TTL = 基础 60s + 随机抖动 ±10s，批量写入错峰过期，避免同一刻批量打库。

### 3. 一致性 = 精准失效 + TTL 兜底

- 变更（版本生命周期操作 / Nacos 配置变更 / Redis 广播）都经 `RuleCacheService.invalidate(key)` 精准清「本地 Caffeine + 跨实例 Redis DEL」；TTL（60s）只做最后兜底上界，不承担实时一致性的主责。
- Nacos 监听 `verify-service.yml` 配置变更，绕过生命周期操作直接改的配置也能秒级回源；监听注册/广播失败均静默降级为 TTL 收敛，不新增故障面。

### 4. Redis 异常透传降级

- Redis 读写、删、锁获取任何异常一律 caught 并降级为「Caffeine + DB」直接读，保持本地返回与回填不受影响——缓存是性能优化，不得因 Redis 抖动阻断校验主链路。
- `cache.two-level.enabled` 总开关（默认 true）可整体退化为单层快路径。

## 备选否决

- **只用 Redis（去掉本地 Caffeine）**：每次读多一次网络 RTT，丢热点加速，且 Redis 抖动直接放大到主链路。
- **只用 Caffeine（维持现状）**：跨实例不共享，每实例各查一次库，热点规则无法命中他实例已回填的副本。
- **为判定结果也上二级**：判定结果有状态机幂等兜底，二级放大引入额外一致性负担，投入产出比低。

## 后果

- 正面：审批版 §7.3 弹药 I 由「讲设计」升级为实锤。真实单测覆盖两级命中路径（本地/Redis/两级未命中回源）、空值缓存、互斥重建（并发仅一实例查库）、TTL 抖动区间、变更精准失效，`mvn clean install` 全绿。
- 代价：读路径新增一层 Redis 分支，复杂度上升（需兼顾降级/互斥/错峰）；`lock:rule-rebuild:*` 与规则 key 占用少量 Redis key。
- 已知边界：Caffeine 空值哨兵沿用共享缓存 1min TTL（不可按 key 设独立过期），本地空值存活略长于 Redis 5s，可接受（本地仅本实例、概率低）；严格并发「仅一个查库」在极端 JVM 内多线程仍可能各回源一次，靠锁等待时间窗把概率压到极低。
