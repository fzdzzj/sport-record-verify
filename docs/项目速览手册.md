# 运动记录真实性校验系统 · 速览手册（不用看源码版）

> 目标：只看本手册即可完全掌握工程全貌。代码细节留到需要时再翻。
> 关联文档：`docs/运动记录校验系统需求文档（审批版）.md`（业务源头）、`docs/adr/0001-版本矩阵与技术选型.md`（选型理由）。

## 0. 一句话定位

**微服务工程**：6 个业务服务 + 1 个网关 + 独立数据库，Nacos 注册/配置中心，Feign 契约先行，
中间件一键编排。**业务逻辑逐步落地：认证鉴权已交付（add-jwt-auth：注册/登录/刷新 + 网关统一鉴权 +
X-User-Id 数据隔离 + refresh 轮换防重放，ADR-0007）；治理面 RBAC 已交付（add-admin-rbac：最小角色
USER/ADMIN + access 携带 role claim + 网关 `/admin/**` 与规则版本接口仅 ADMIN 可达，ADR-0007）；
登录爆破防护闭环已交付（add-login-lockout：窗口内失败达阈值账号临时锁定，入口直接拒绝、自动解锁、成功清零）；
好友模块已交付（双向好友 + Redisson 锁防并发互加）；
点赞模块已交付（Redis 计数 + 异步批量落库 + 对账）；排行榜模块已交付（Redis ZSet 热读 +
事件驱动入榜/回滚 + 定时快照结算防重）并拆为独立 leaderboard-service（服务数 4→5，ADR-0005）；
道路拓扑匹配已交付并独立为 mapmatch-service（服务数 5→6，ADR-0006：真实 OSM 路网 + 最近边投影，
R5 离路规则把校验引擎升级为「规则链 + 空间真实性」双保险）；
校验引擎判定算法 R1-R5 已在 verify-service，压测待后续变更**，本骨架是各变更的稳定基线。

| `api` | 跨服务契约（只定义不实现） | `RecordApi` / `VerifyApi` / `UserApi` / `LeaderboardApi` / `MapMatchApi` / `AuthApi` + DTO（`SportRecordDTO`、`TrackPointDTO`、`VerificationResultDTO`、`UserDTO`、`LeaderboardDTO`、`MapMatchResultDTO`、`TokenDTO`、`RegisterRequestDTO` 等） |

| `user-service` | 用户域（好友域 + **认证域**） | `UserApplication`、`InternalFriendController`、`InternalUserController`、`AuthController`（注册/登录/刷新）、`AuthService`（BCrypt + 手机号唯一 2001 + 失败计数 + 达阈值账号锁定 auth:lock + `grantAdmin` 内部授予 ADMIN）、`JwtUtil`（HS256 双 token 签发，access 携带 role claim，refresh 轮换存 Redis）、`User`（含 role 字段默认 USER） |

| `verify-service` | 校验引擎 + 申诉 + 规则灰度 | `VerifyService`（判定/申诉）、`VerifyEngine` + R1-R5 规则链（`R5OffRoadRule` 首个远程规则，Feign 调 mapmatch + 熔断降级不命中）、`RuleVersionService`（灰度采样路由/回滚/全量）、`RuleVersionController`（管理端点）、`VerifyEventConsumer`（SUBMITTED 消费）、`RuleCacheInvalidationListener`（缓存失效广播） |
| `leaderboard-service` | 榜单读热 + 事件沉淀 | `LeaderboardService`（入榜/回滚/总榜/好友榜/快照结算）、`LeaderboardEventConsumer`（VERIFIED/REJECTED 独立消费组）、`SportRecordMapper`（只读快照，无写方法）、`LeaderboardController` / `InternalLeaderboardController` |
| `mapmatch-service` | 道路拓扑匹配（空间真实性） | `MapMatchService`（最近边投影两段式：GIST 预筛 + Java 垂距，采样 200 点上限）、`MapMatchController`（`POST /match`）、`MatchProperties`（吸附 25m/半径 300m/采样上限可配）；`scripts/mapmatch/` 路网导入脚本 |

## 4. 数据库速览（审批版 §6，脚本在 `sql/`，幂等可重放）

**user_db**
| 表 | 用途 | 关键设计 |
| --- | --- | --- |
| `user` | 用户 | `phone` 唯一；`role` 默认 USER（ADMIN 经内部接口授予，治理面准入） |
| `friend_request` | 好友申请 | 状态机 PENDING/ACCEPTED/REJECTED/CANCELLED；`(to_user,status)` 索引 |
| `friendship` | 好友关系 | **`user_low < user_high` 主键**，从根上消除 A-B/B-A 重复行 |

**record_db**
| 表 | 用途 | 关键设计 |
| --- | --- | --- |
| `sport_record` | 运动记录 | `request_id` 唯一（幂等键）；`version` 乐观锁 |
| `track_point` | 轨迹点 | **分片键 `user_id % 16`**（骨架阶段为逻辑表，分片配置随校验引擎变更启用） |
| `leaderboard_contribution` | 榜单贡献（**归属 leaderboard-service**） | `record_id` 主键 = 回滚锚点（驳回/改判据此回滚）；表复用 record_db，物理隔离拆库为可选 |
| `record_like` | 点赞 | `(record_id,user_id)` 联合主键 = 天然幂等防重复赞 |

**verify_db**
| 表 | 用途 | 关键设计 |
| --- | --- | --- |
| `verification_result` | 校验结果 | `record_id` 主键；`rule_hits` JSON 存判定证据（含 R5_OFFROAD） |
| `appeal` | 申诉 | `record_id` 唯一（一条记录一个申诉单） |
| `rule_version` | 规则版本 | `version` 唯一；`gray_ratio` 灰度比例 0-100 |

**road_db（PostGIS，mapmatch 专用空间库）**
| 表 | 用途 | 关键设计 |
| --- | --- | --- |
| `road_edge` | OSM 道路边表 | `geom` LINESTRING(4326) + **GIST 空间索引**（ST_DWithin 候选边预筛）；`road_level` 1-5 道路等级；由 `scripts/mapmatch/import-road-network.sh` 幂等导入真实 OSM 切片 |

## 5. 统一错误码表（`ResultCode` 枚举，对应审批版 §4.8）

| 段 | 码 | 含义 |
| --- | --- | --- |
| 成功 | 0 | success |
| 1xx 认证 | 1001 / 1002 | token 无效或过期 / 无权限（越权） |
| 2xx 用户 | 2001 / 2002 | 手机号已注册 / 用户不存在 |
| 3xx 记录 | 3001~3004 | 记录不存在 / 无权访问 / 状态不允许 / 幂等冲突（返回原结果） |
| 4xx 校验 | 4001~4005 | 校验服务不可用（降级转人工）/ 规则版本不存在 / 版本状态不允许该操作 / 版本冲突（重复号·已有采样·比例越界）/ 匹配服务不可用（mapmatch 熔断降级，R5 降级不命中） |
| 5xx 好友 | 5001 / 5002 | 重复申请或已存在关系 / 关系不存在 |
| 6xx 点赞 | 6001 | 记录未通过校验不可点赞 |
| 兜底 | 9999 | 系统繁忙（对外不泄漏堆栈） |

## 8. 各服务关键配置（application.yml）

| 配置 | 作用 | 备注 |
| --- | --- | --- |
| `spring.config.import: optional:nacos:{app}.yml` | 从 Nacos 拉配置 | `optional:` → Nacos 挂了也能启动，注册持续重试并报错指向 Nacos |
| `spring.datasource.*` | 各服务连自己的库 | user→user_db，record→record_db，verify→verify_db，leaderboard→record_db（贡献表同库） |
| `hikari.initialization-fail-timeout: -1` | 骨架容错 | 中间件没起也能启动；生产建议改回 fail-fast |
| `spring.shardingsphere.enabled: false` | record 分片开关 | 依赖已引入、能力关闭，随校验引擎变更启用 |
| `spring.cloud.sentinel.enabled: false` | gateway 限流开关 | 仅引入依赖预留 |
| `rocketmq.name-server: 127.0.0.1:9876` | record/verify/leaderboard 消息 | producer 自动装配；leaderboard 侧另有独立消费组 `leaderboard-consumer-group` |
| `spring.data.redis.*` | Redisson / ZSet / 计数 | starter 自动装配 RedissonClient（懒连接） |

## 9. Feign 契约速查（api 模块，接口与实现分离）

| 契约接口 | 声明路径 | 实现位置 | 说明 |
| --- | --- | --- | --- |
| `RecordApi` | `record-service` `/internal/**` | record-service `InternalRecordController` | 探活 + 拉记录/轨迹/状态回调 + 点赞三接口 |
| `VerifyApi` | `verify-service` `/internal/**` | verify-service `InternalVerifyController` | 探活 + 判定结果查询 + 申诉创建 + 重校验 |
| `UserApi` | `user-service` `/internal/**` | user-service `InternalFriendController` 等 | 探活 + 好友四接口 + 批量用户概要（榜单昵称补齐） |
| `LeaderboardApi` | `leaderboard-service` `/internal/leaderboard` | leaderboard-service `InternalLeaderboardController` | 榜单查询契约（自 RecordApi 迁出，服务数 4→5） |
| `MapMatchApi` | `mapmatch-service` `/match` | mapmatch-service `MapMatchController` | R5 离路规则远程匹配（服务数 5→6）；FallbackFactory 抛 4005，R5 降级不命中 |

跨服务调用演示：`GET /verify/internal/probe/record`（verify → Feign(RecordApi) → record），后续校验引擎拉轨迹就是这个模式。
> 注意：Cloud 2023.0.x 的 openfeign 不再传递 `spring-cloud-starter-loadbalancer`，需显式声明（已加）。

## 10. 一键命令

```bash

java -jar user-service/target/sport-verify-user-service-0.1.0-SNAPSHOT.jar
java -jar record-service/target/sport-verify-record-service-0.1.0-SNAPSHOT.jar
```

## 12. 关键设计决策（ADR-0001 摘要）

1. **Boot 3.2.4 不升 3.3**：SCA 2023.0.1.0 官方兼容矩阵只覆盖 Boot 3.2.x，升 3.3 引入版本冲突。
2. **RocketMQ 独立 starter 2.3.1**：SCA 不内置 RocketMQ，官方独立集成。
3. **MySQL 单实例三库**：开发环境资源友好，连接层完全隔离；物理隔离改 compose 即可。
4. **ShardingSphere 仅接入默认关闭**：分片与校验引擎变更强耦合，本提案只铺依赖不实现（一个提案一个关注点）。
5. **JDK 强校验**：enforcer 要求 JDK≥21，低于直接编译失败并明确提示。
6. **Nacos 配置用 `optional:` 导入**：Nacos 不可用不阻塞启动（生产可去掉 optional 强制依赖）。

## 14. 速记（30 秒版，诚实口径）

- **为什么网关**：统一入口、隐藏服务实例拓扑，路由失败返回 503 不泄漏内部结构。
- **接口与实现分离**：api 模块只放契约，服务实现，编译期锁契约，防漂移。
- **为什么 5 个服务**：榜单读多写少可独立扩缩容、数据热点隔离（ZSet+贡献表与记录分片分开）、故障面隔离（榜单抖动不拖累记录主链路）；拆分代价是多一服务的部署开销——进程拆分优先于数据拆分（贡献表复用 record_db）。
- **为什么 6 个服务/空间匹配**（ADR-0006）：R1-R4 识别不了「轨迹不在任何真实道路上」的悬浮伪造——R5 把轨迹吸附到真实 OSM 路网算离路比例；空间数据/算法独立成 mapmatch-service（资源画像不同、可独立演进换 HMM、故障面靠熔断隔离）。为什么 PostGIS：ST_DWithin+GIST R-Tree 是空间查询事实标准；为什么先最近边投影：判定目标是粗粒度占比而非精确重建路径，最小可用版先跑通闭环；为什么真实 OSM：单城市切片（Overpass，与压测样本同基准）才讲得了全国分片/瓦片的工程化。
- **R5 降级口径**：mapmatch 挂 → Resilience4j 熔断 FallbackFactory 抛 4005 → R5 捕获降级「不命中」记 warn——路网匹配是增强证据非强依赖，宁可放过不可阻断校验主链路（与 T11 同熔断参数）。
- **拆分防双写三板斧**：record 侧消费者下线（单消费组）、sport_record 只读 Mapper（结构上无写方法）、路由前缀随职责切换。
- **幂等设计**（骨架已铺好）：`request_id` 唯一键、`record_like` 联合主键、`friendship` 规范化主键、`sport_record.version` 乐观锁。
- **分片预留**：track_point 按 `user_id % 16`，冗余分片键保证路由。
- **灰度三件套**：userId%100 采样同用户恒定同分支；库内 rules_json 快照隔离 Nacos 观察期竞态；gray_ratio=0 秒回滚（本实例即时失效 + Redis 广播扇出，60s TTL 兜底）。
- **阈值按类型分维度**（ADR-0004 §5）：R1-R4 按 sportType 独立标定（RUNNING 5.5/CYCLING 15/WALKING 3.5，per-sport-type 标定口径：真实运动数据分位数）——骑行正常 6~8 m/s 不再被 R1 误杀；缺省回退 RUNNING 保历史行为；快照旧扁平结构回退单套、灰度与类型正交。
- **二级缓存**（ADR-0008）：规则快照/灰度路由读路径升级为 Caffeine → Redis → DB 回填两级（`RuleCacheService`）；穿透=空值哨兵(5s)、击穿=Redisson 互斥重建(锁等待 3s)、雪崩=TTL 60s±10s 抖动；Nacos/版本变更精准失效 Caffeine+Redis DEL，TTL 只做兜底；Redis 异常自动降级 Caffeine+DB 不阻断校验。判定结果缓存维持单层 Caffeine（有状态机幂等兜底）。
- **诚实说明**：本工程是业务基线，各模块已交付的能力以「已验证事实」为准，勿把预留当已实现。
