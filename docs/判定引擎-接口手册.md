# 判定引擎 — 接口手册

> 配套《判定引擎-开发总览.md》。所有接口统一返回 `Result{code, message, data}`；`code=0` 成功，其余见文末错误码表。示例基于本地验收实测（8082/8083 直连，生产经网关前缀 `/record/**`、`/admin/**`）。

---

## 1. 记录域（record-service :8082）

### 1.1 提交运动记录（含幂等）

```
POST /api/records
```

请求体：

```json
{
  "requestId": "client-request-001",      // 客户端幂等键（唯一，重复提交返回原结果）
  "userId": 100,
  "sportType": 1,                          // 1=RUNNING
  "startTime": "2026-01-01T08:00:00",
  "endTime": "2026-01-01T08:03:00",
  "distance": 0.54,                        // 公里
  "duration": 180,                         // 秒
  "points": [
    { "seq": 0, "lat": 39.9, "lng": 116.4, "ts": 1767225600000, "speed": null },
    { "seq": 1, "lat": 39.90008, "lng": 116.4, "ts": 1767225603000, "speed": null }
  ]
}
```

首次提交响应（记录状态 1=VERIFYING，判定异步进行）：

```json
{ "code": 0, "message": "success",
  "data": { "recordId": 7, "status": 1, "duplicated": false } }
```

重复提交（同 requestId）响应：**code=3004**，data 携带原结果（同一 recordId + 当前状态）：

```json
{ "code": 3004, "message": "重复提交，返回原结果",
  "data": { "recordId": 7, "status": 2, "duplicated": true } }
```

### 1.2 查询判定结果

```
GET /api/records/{recordId}/verify-result
```

响应（`ruleHits` 为证据 JSON 字符串，`verdict`：0=校验中 / 1=通过 / 2=拒绝）：

```json
{ "code": 0, "message": "success",
  "data": {
    "recordId": 7, "verdict": 1, "score": 50, "checkedAt": "2026-09-11T16:45:29",
    "ruleHits": "{\"hits\": [], \"score\": 50, \"verdict\": \"PASSED\",
                  \"preprocess\": {\"pointsTotal\": 60, \"driftRemoved\": 0, \"driftRatio\": 0.0}}"
  } }
```

伪造轨迹（匀速 6m/s）的判定证据示例：

```json
"ruleHits": "{\"hits\": [{\"rule\": \"R1_SPEED\", \"level\": \"HARD\",
   \"detail\": \"window avg 6.0 m/s over 120 points (seq 0-119)\"}],
   \"score\": 70, \"verdict\": \"REJECTED\",
   \"preprocess\": {\"pointsTotal\": 120, \"driftRemoved\": 0, \"driftRatio\": 0.0}}"
```

### 1.3 提交申诉（仅 REJECTED 记录）

```
POST /api/records/{recordId}/appeal
```

请求体：`{ "reason": "请求人工复核" }`（userId 可省略，服务端以记录归属人为准）

响应（申诉单 status：0=待复核）：

```json
{ "code": 0, "message": "success",
  "data": { "id": 2, "recordId": 8, "status": 0, "reason": "请求人工复核" } }
```

非 REJECTED 记录申诉 → **code=3003**「状态不允许该操作」。

### 1.4 轨迹分页查询（分片分页）

```
GET /api/records/{recordId}/points?page=1&size=10
```

响应：

```json
{ "code": 0, "message": "success",
  "data": { "total": 60, "size": 10, "current": 1, "records": [
    { "id": 123, "recordId": 7, "userId": 100, "seq": 0, "lat": 39.9, "lng": 116.4, "ts": 1767225600000, "speed": null }
  ] } }
```

## 2. 校验域（verify-service :8083）

### 2.1 管理员终判（网关前缀 /admin/，StripPrefix=1）

```
POST /admin/api/appeals/{appealId}/review
```

请求体：

```json
{ "operator": "admin", "pass": false, "recheckResult": "复核确认异常" }
```

- `pass=true` → 记录 RE_PASSED(5)、申诉单 RE_PASSED(1)
- `pass=false` → 记录 RE_CONFIRMED(6)、申诉单 RE_CONFIRMED(2)

响应：`{ "code": 0, "message": "success", "data": { "id": 2, "status": 2 } }`

非 PENDING 申诉终判 → **code=3006**；申诉单不存在 → **code=3005**。

## 3. 内部接口（服务间 Feign 调用，鉴权在网关层）

| 服务 | 接口 | 说明 |
|---|---|---|
| record-service | `GET /internal/records/{id}` | verify 拉取记录（含版本号做乐观回调） |
| record-service | `GET /internal/records/{id}/points` | verify 拉取轨迹明细 |
| record-service | `POST /internal/records/{id}/status-callback` | verify 回调状态，体 `{recordId, status, version}` |
| verify-service | `GET /internal/verify-results/{recordId}` | record 查询判定结果 |
| verify-service | `POST /internal/appeals` | record 建申诉单（体 `{recordId, userId, reason}`，幂等） |
| verify-service | `POST /internal/records/{recordId}/verify` | **MQ 降级兜底/人工重放**：触发判定（幂等，重复调用无副作用） |

## 4. 错误码速查

| code | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | — |
| 3001 | 记录不存在 | 查/申诉/终判目标记录不存在 |
| 3003 | 状态不允许该操作 | 非 REJECTED 申诉、乐观锁冲突 |
| 3004 | 重复提交 | 同 requestId 再次提交 |
| 3005 | 申诉不存在 | 终判的申诉单不存在 |
| 3006 | 申诉状态不允许该操作 | 非 PENDING 被终判 |
| 4001 | 校验服务暂不可用 | verify 降级不可达（申诉创建失败） |
| 9999 | 系统繁忙 | 未预期异常（对外不泄漏细节） |

## 5. 快速冒烟（curl）

```bash
# 提交真实轨迹（30 点，3m/s）
curl -X POST http://127.0.0.1:8082/api/records \
  -H 'Content-Type: application/json' \
  -d '{"requestId":"smoke-1","userId":200,"sportType":1,"startTime":"2026-01-01T08:00:00","endTime":"2026-01-01T08:01:30","distance":0.27,"duration":90,
       "points":[{"seq":0,"lat":39.9,"lng":116.4,"ts":1767225600000},{"seq":1,"lat":39.90008,"lng":116.4,"ts":1767225603000}]}'

# 查询判定结果（返回 verdict/score/ruleHits）
curl http://127.0.0.1:8082/api/records/1/verify-result

# 分片落位验证（user 200 → track_point_8）
mysql --host=127.0.0.1 -uroot -p1234 -e \
  "SELECT COUNT(*) FROM record_db.track_point_8 WHERE user_id=200;"
```
