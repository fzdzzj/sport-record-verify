# 面试项目 · 执行计划（3.5 个月版 / 15 周）

版本：v2.2 ｜ 适用：有微服务经验、窗口 3.5 个月（可压缩至 2 个月）、明年面试

---

## 0. 前提与诚实结论

- 你有微服务经验 → 无学习期，直接进骨架与实现。
- **全职（40h/周）**：15 周非常从容，P0+P1 全部做完还留缓冲；
- **业余（~20h/周）**：主线 + P1 够用，P2 按第 3 节砍。
- **贯穿性提醒（最重要）**：项目做完到明年面试之间有空窗。**代码会忘，沉淀不会。** 每周 commit、每月一篇笔记、Q&A 边做边写——这三件事从第 1 周开始做，不是最后补。
- **AI 分工（你的要求）**：后端以你写为主（AI 可辅助，但每一行都要能讲透）；前端页面由 AI 生成，但你仍需投入时间——**前端相关总时间控制在项目总投入的 10-15%**（定接口契约、review 页面代码、联调、能讲清页面如何调后端），集中在 W9，其余周每周 ≤1-2 小时。面试话术：「前端是 AI 辅助生成的，我负责接口契约、数据模型与联调」——诚实说明是加分项（展示工具使用能力），但绝不能装成手写。

## 2. 十五周周计划

### 主线（W1-W6，与 2 个月版一致但更从容，每块都配测试）

| 周 | 目标 | 产出 |
| --- | --- | --- |
| W1 | 环境与骨架：JDK21/Maven/Docker、**版本矩阵验证（SCA 2023.0.1.0 + Boot 3.2.4 兼容趟坑）**、Nacos+MySQL Compose、4 服务空工程、Gateway 路由、注册发现、Feign 空链路 | `docker compose up` 后 Nacos 控制台 4 实例 |
| W2 | user-service：注册/登录/JWT、user_db、网关鉴权过滤器 | 登录拿 token，网关校验通过 |
| W3 | record-service：提交接口、**ShardingSphere 分片配置（轨迹点表）**、轨迹点分表落库、状态机 v1（SUBMITTED→VERIFYING） | 记录落库可查、分片生效 |
| W4 | verify-service：预处理（漂移过滤）+ 规则链 v1（速度/加速度/停留/距离一致性）+ **Caffeine 规则缓存 + Sentinel 熔断** + 判定证据 JSON；Feign 链路打通 | 提交→校验→判定闭环第一次跑通 |
| W5 | 幂等（request_id+唯一索引+乐观锁）、申诉改判、状态机终态（PASSED/REJECTED/RE_PASSED/RE_CONFIRMED） | 改判可回滚 |
| W6 | 榜单（仅 PASSED + 贡献快照 + 回滚）、阈值迁 Nacos 配置中心动态刷新 + **规则灰度版本**、**Sentinel 网关限流**接入、单测补齐 | 动态调阈值生效、限流生效 |

> **可选增强（+1.5 周，推荐）**：双向好友（申请/同意）+ 对运动记录点赞 + 好友榜（Redis ZSet），插入 W6 与 W7 之间；设计见《微服务面试项目方案》"好友与点赞"小节。2 个月档则砍掉（讲设计）。

> **算法与八股（已确认：考前突击）**：W2-W12 每周保持 1-2 题热身（防生疏）；W13-W15 集中突击（高频 150 题 + 八股主题：MySQL/Redis/RocketMQ/JVM/并发）。诚实风险提示：算法纯突击风险高，W10 起转入冲刺节奏。W8 压测与优化实录（Explain 慢查询、GC、连接池、P95 对比）照常。

## 3. 若压缩到 2 个月的砍法（预案）

- 前端可视化保留（AI 生成成本低）→ 先砍压测细节（只记 P95 不写报告）→ 其次砍 W12 报告成文（README 里留要点）；
- 永不砍：闭环能跑、单测、README + ADR、演示视频、Q&A 稿。

## 4. 贯穿项（每周都做，不是收尾任务）

1. 每周 commit（消息规范，本身是面试谈资）；
2. 每月一篇项目笔记：设计决策 + 踩坑记录（Nacos 版本兼容、Feign 超时、分片键选择等）；
3. Q&A 稿边做边写：每完成一个模块，当晚记 3-5 条"面试官会问什么"并写答案；
4. **接口契约先于前端**：前端是 AI 写的，所以接口和数据模型必须你先定死（字段、状态码、错误格式），AI 生成页面才有依据——这本身就是后端基本功的体现；
5. **前端时间预算**：除 W9 外每周前端相关 ≤1-2 小时（契约变更/联调），不占用主线；前端目标是"能演示、能讲清对接"，不是深入前端框架。

## 5. 面试（明年）前的收尾
